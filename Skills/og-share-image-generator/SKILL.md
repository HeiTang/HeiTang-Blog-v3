# OG 社群分享圖生成器

## 定位與參考

讓分享卡片清楚傳達「這頁在講什麼」，並一眼辨識為 purr.tw 同一系列。採文字優先的平面資訊設計，不把網站的玻璃 UI 效果轉成 3D 插畫。

生成前先用圖片檢視工具查看以下既有成品，並將 PNG 作為 imagegen 的風格參考輸入。相對路徑以本 Skill 所在目錄為基準：

- [concerts.png](../../src/assets/og/concerts.png)：標準左文右圖、文字層級與留白。
- [japan.png](../../src/assets/og/japan.png)：平面幾何圖形與同色系分級。
- [default.png](../../src/assets/og/default.png)：品牌基調、背景與克制的裝飾。

同名 SVG 可用於核對色碼、尺寸及字體規格；生成時以 PNG 的可見外觀對齊。不要將舊卡片的主題文案、地圖或音量柱複製到無關頁面。

## 版型

以 **1200 × 630 px** 畫布為基準；下列座標為設計錨點，文字 y 值指基線，可隨標題行數微調。

| 區域 | 位置與規則 |
| --- | --- |
| 背景 | 滿版深色緩和漸層；44–48 px 方格，1 px 白線、約 3.5% 不透明度 |
| 品牌短線 | 左上 `(72, 82)` 至 `(188, 82)`，橘色、8 px、圓端點 |
| 英文眉標 | 左側 `(72, 194)` 附近；說明主題類別 |
| 主標題 | 左側 x≈72，首行基線 y≈285–300；最多兩行，右界約 x=745 |
| 副標題 | 主標題下方留 24–32 px 視覺間距；一行為優先 |
| 主題圖形 | 右側約 x=780–1128、y=180–450；留出與文字的間隔 |
| 主題關鍵字 | 左下 `(76, 514)` 附近；內容不足時可省略，不塞填充詞 |
| 站名 | 右下 `(1128, 574)`，向右對齊；預設 `PURR.TW` |

重要文字距四邊至少約 64 px。長標題先合理換行或精簡非必要字詞，不水平壓縮、不縮成難讀小字；使用者指定的原文不得擅自改寫。需要兩行主標題時，副標題順延，仍須與底部資訊分離。

## 色票

| 用途 | 色碼 |
| --- | --- |
| 背景起色 | `#0f1419` |
| 背景終色 | `#1a1f2e`；需要較亮右側時可用 `#252b3b` |
| 主色、眉標、短線 | `#ff8c61` |
| 次要橘色文字 | `#ffb4a2` |
| 主標題 | `#ffffff` |
| 副標題 | `#d1d5db` |
| 少量輔色 | `#9d7fe8`，只作小面積重點 |
| 幾何圖形的橘色階 | `#ffe3d6`、`#ffc1a5`、`#ff9a6f`、`#f66f41`、`#c9461f` |

文字保持純色；大面積維持深色背景。不要加入霓虹光暈、金屬反射、玻璃材質、立體陰影或新的配色主題。

## 字體與文字層級

| 文字 | 字體方向 | 尺寸／字重 |
| --- | --- | --- |
| 繁體中文主標題 | Noto Sans TC，無襯線；英文搭配 Inter | 短標題約 70 px／700，長標題約 56–64 px／700 |
| 副標題 | Noto Sans TC／Inter | 28–30 px／400 |
| 英文眉標 | JetBrains Mono，全大寫 | 24–26 px／600，字距 5–6 px |
| 關鍵字、站名 | JetBrains Mono | 20–22 px／400 |

生成模型的字體名稱與色碼是視覺目標，不代表能保證使用實際字型檔。需檢查字形、筆畫、粗細與參考圖一致；不得把近似字體描述成精準套用。避免書法、襯線、立體字與漸層字。

## 每張圖應呈現的內容

先讀目標文章或頁面，以內容決定下列欄位；只在關鍵資訊缺失時詢問使用者：

- **英文眉標**：短而具體的主題名稱，不是宣傳口號。
- **繁體中文主標題**：頁面名稱或忠於內容的精簡題名；保留辨識主題所需的產品／技術名稱。
- **副標題**：一句說清楚內容或用途，不捏造效益、數字、優惠或成果。
- **關鍵字**：通常 2–3 個相關詞，以 ` · ` 分隔；可省略。
- **站名**：`PURR.TW`；只有需要且路徑已確認時才加簡短頁面識別。
- **右側圖形**：用一組主題相關的矩形、線條、色塊或簡單符號表達內容。正面平面構圖，不加場景、透視、寫實物件或與內容無關的角色。

不要固定套用過往文章的標題、說明或圖案。新卡片應保持系列一致，但主題必須有內容差異。

## 生成與驗收

1. 使用 **imagegen Skill 與內建 image_gen 工具**，每個主題各呼叫一次；將參考 PNG、上述視覺規格及此次確定的逐字文案一起傳入。不要只給「科技感」等模糊風格描述，也不要以手寫 SVG 代替使用者要求的圖片生成。
2. 指定橫式 1200:630 比例；用既有 `sharp` 做最終尺寸與編碼整理。若比例不符，不拉伸文字，改用不傷及安全區的裁切，必要時重新生成。
3. 以完整尺寸和約 600 × 315 的分享預覽尺寸檢查：繁體字、英文字母、字距、文字是否正確且清楚，文字與圖形無重疊、裁切，與三張基準圖具有相同風格。發現問題時針對單一偏差修正。
4. 預設將成品存至專案 `src/assets/og/`，檔名使用描述性小寫 kebab-case。JPEG 品質 88、mozjpeg 可作起點；以清楚文字與避免色帶為優先，目標每張小於 200 KB。不要只留在工具的生成目錄，也不必把每次的完整 prompt 存入 repo。
5. 只有任務包含頁面整合時才修改程式：Astro 頁面 import 後使用 `.src`；文章沿用 `cover` 的 `image()` schema。建置後確認 OG、Twitter、文章 JSON-LD 使用同一張圖的公開絕對 URL，實際尺寸為 1200 × 630。

交付成品預覽、專案內路徑與實際驗證結果。這份 Skill 只維護可重用的 OG 設計規範，不收錄逐張生成紀錄、favicon 處理、動畫轉檔或部署快取工作。
